# TS-305：无主语话题回指与未知人物区分

基线 `b33cebb1235f56fa6155c1b14c0942bd5fa4c66d`，分支 `codex/ts-305-memory-q20`。本任务仅为本地候选，未合入 main、推送或部署；实际 PostgreSQL 与完整 210 输入复测由协调者执行。日常 Gemini、真实记忆、QQ、媒体和挂载均未操作。

## 根因和改动

恢复轮中“刚才群里提到的那只猫叫什么？”被既有语言规则归一为“提到的那只猫叫什么？”，弱 `X那只` 形式把“提到的”当成未知人物。`named_owner` 因没有此人物的当前姓名见证而返回空候选。实际桃酥、蜜枣记录在提问前的 900 秒快照已经提交，后置只读证据按原回执记录核对了事实值、owner、完整组、原始来源和物理作者；当次真实业务 prompt 均未含猫名。因此不能归因晚提交，也不是模型忽略已给出的名字。实际结果和来源证据保持原样，本任务不修改真实记忆。

仅修改 `recall_language.py`，新增相关测试文件。正向、锚定且没有说话人名称的报告框架使用一个 `_subjectless_target`：复用已有时间引导词、报告动词和有限对象校验，返回原样的对象部分。人物分类不再把这些引导词当作姓名；对象词法焦点不再要求事实同时包含“前面说过”等无关词；报告中的“之前”也不再把当前名称问题误判成对象历史。对象自身的“以前、旧名、现在”等仍保留。

对象校验由原具名来源分支提取复用，没有新增另一套对象词典。`named_owner` 的当前 canonical 姓名见证仍优先：合成用户真的叫“提到的”时，问题仍限定该人并携带完整姓名组，不因无主语语法而回退另一人的同题事实。真正未知姓名、否定/条件、多人来源、二级拥有者及引文边界维持原规则。无主语且同群有两只猫时返回两位已授权 owner 的原记录，不伪造唯一人物。

没有修改 Constraints、ranker、SQL、候选上限、scope、来源核验、schema、存储数据或配置。Source-speaker 与实体拥有者的职责没有变化，也没有新增 parser 类、缓存或 I/O。

## 限制与交接

这里支持有限正向报告语法与已有对象词汇，不声称理解任意中文省略、未知昵称或复杂多句指代。不确定的二级拥有者等没有被删掉以强求命中；陌生人物的私聊/跨群事实也不会因为同题查询变得可见。词法处理不修改原查询、原记录 statement 或最终输出内容。

新增 7 个 PG 节点的精确名称来自实际 XML，协调者可运行 `tests/test_discourse_reference.py -k postgresql`。未重复全 Memory 或未变原生套件。本任务不解决调度门后的超期恢复、未知回执退避或 Platform 轮询问题，分别由本轮其他独立卡负责。完整 210 测试须在全部候选冻结后使用新隔离 UUID 执行；原失败 134 输入、原 900 秒窗口和此前所有评分继续保留，不能由后续成功覆盖。
