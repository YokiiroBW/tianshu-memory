## 变更与用户可见行为

- 新增 POST `/internal/v1/memory/profiles/select`。调用方需在现有 operations 中显式获准
  select_profiles；从现有 contract_directory 的 contracts 根定位发布包，无新配置键。
  旧配置不加载新包，仍只提供旧路由。没有获准新操作403，未显式迁移503。
- 请求人的可信 requester_scope 与 person/group target 分离。群用已核验的核心会话 ID，
  不能伪装人物；字段/类别、subject、受众、当前版本和完整语义组逐项核对。
- group_only 限精确群，支持同人在两群的不同风格和独立群主题。public_preference 限
  同 actor 获准场景的明确批准人物兴趣；群内本人披露的兴趣也可按单独公共批准分享。
  旧群批准不能复用于公开范围，群主题只能来自该群来源，观察可保留 inferred。
- 只取当前有权投影，不查询目标私人目录。未知目标/仅有私密内容相同空选择/no_match；
  无原文血缘、私聊经历、隐藏计数或好感数值输出。投影来源引用重新由 memory 签发。
- 复用现有记录/来源血缘/版本/索引/失效事务，以及 TS-030 精确字段缩候选、词项覆盖+
  BM25、完整组预算、零预算只读元数据。新主体存储带标记，不混入旧 v1 查询。
- version_domain=profile-memory/v1 与旧 v1 scope_version 独立。公开 epoch 与当前群 epoch
  只受实际共享变更影响，私人记录和其他群独有变化不泄漏到当前版本。
  更正/遗忘/来源撤回同事务使全部依赖投影与对应 epoch 失效；重启保持该状态。
- schema 1→2 显式 migrate-profiles，先留完整 SQLite 备份再事务内增表；DDL失败回滚。
  旧记录保留且不会自动公开；旧程序拒绝 schema 2。回滚边界见 docs/profile-runtime.md。
- LocalWorkflow 和 fixture-action 提供合成的精确批准/单次发布，没有共享 HTTP 写入口。
  不把模型标记、服务令牌或普通字段当同意；生产授权策略/确认 issuer 尚未接入。

## 未接入与风险

SQLite/LocalFixtureSources 属组件验证，生产来源、共享策略签发和撤销、PostgreSQL、
embedding、真实 L0/L1 未接。已确认字段/类别/范围策略可用于未来受控发布，不要求
逐项弹窗；当前合成精确批准不是真实用户同意，群夹具整理不代表任意成员有群授权。
核心画像客户端单列后续任务，不由本任务自行启动。没有生产命令默认值或真实账号/NAS操作。

无服务响应缓存且HTTP no-store；发送前须用本版本域复核，不能混用旧v1相同整数版本。
复核与外部发送之间不是分布式原子保证。回滚旧备份不包含备份之后数据，须另行保留并
评审恢复；没有丢弃新数据的原地降级。遗忘的物理擦除及备份清除仍未实现。
