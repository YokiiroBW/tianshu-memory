## Implementation

Every PG `SourceAuthority.revision` now gets the lookup marker, revision, recovery
state and current-schema index count in one native read instead of four statements.
The marker, index count, revision/recovery and integer conversion retain their
original validation order. All six normal invocation points remain, including
coverage's own checks and the result after `_apply`. Nothing reuses Store's earlier
metadata, a prior call's state or a result across transactions. SQLite retains its
original four statements and fault short circuits.

Index-name catalog reads use `pg_class` joined to the current namespace, restricted
to index relation kinds. Other-schema indexes and same-name ordinary tables cannot
satisfy readiness. The original name-existence rule remains; no new index definition,
validity or readiness flags were imposed. Store's lock, fresh metadata snapshot,
guard verification, after-checkpoint and persist-before-commit order were not edited.

PG group and raw automatic-fact reads use a common bound of 512 IDs, formerly 128.
Source admission/suppression and projection reads keep the 256-key bound. Complete
current authorization still precedes record-body reads, candidate order is retained,
and all scope/member/record/version/group/person/projection checks remain. SQLite
does not enter these batch paths.

BM25 materializes the original `plainto_tsquery` once per query term and retains only
ID/vector in the document CTE. Full-corpus length/average/DF, the parser's compound
lexemes, the original matching predicate, OR zero-score hits, constants and Python
ranking/tie rules remain. No schema or persistent index migration is needed.

Design: [pg-read-performance.md](../pg-read-performance.md).
