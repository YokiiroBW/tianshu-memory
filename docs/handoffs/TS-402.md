## Confirmed defects and fixes

1. **Forgetting could miss old text across an expired replacement.** Create long-lived
   interpretation A, replace it with short-lived B, then long-lived C. Maintenance
   erased B's text *and its replaces edge*. Forgetting C could then reach B but not A,
   leaving A's original body stored. `erase_derived` now persists only replacement
   IDs in actor-scoped existing metadata before erasing a payload. Impact and forget
   closure read those body-free edges, including after reopening the Store.

2. **Combining separately forgotten evidence could resurrect an interpretation.**
   Forget same-kind interpretations from A and B separately. A late proposal based
   solely on A+B passed each individual suppression check by using the other old
   source as supposedly new evidence. Suppression now compares against the union
   of that actor/kind's forgotten episode and original-source identities. A truly
   new independent source still permits a new sourced interpretation.

Both scenarios failed on the unchanged base in the two targeted regressions
(`.runtime/tests-402-repro.xml`). The fixes do not modify the public wire, original
source owners, user-memory interpretation or unknown/idempotent receipt semantics.

## Related local cost reductions

- `checkpoint` now reads only schema/instance/revision/recovery by their existing
  primary keys, rather than copying every retained suppression and maintenance
  metadata row on every actor transaction.
- Replacement closure now builds an adjacency map and traverses it once. This
  replaces repeated full-edge scans for each chain depth while retaining the full
  dependency closure. It still reads the actor's existing derived records; no
  unsafe truncation or claim of constant total history cost is made.

These are code-path/complexity improvements, not a measured production latency claim.
No pressure benchmark, new dependency, index/DDL or extra background worker was added.
No implementation was deleted: reviewed migration and CLI entry points have live
callers or explicit compatibility responsibilities.

## Remaining limits / integration

The change preserves replacement IDs when bodies are erased **after this fix**. If
an earlier version already erased a middle node's replaces information, that lost
edge cannot be recovered precisely from current data. This task neither guesses
that relationship nor reads old backups to reconstruct it. Existing retained edges
continue to participate in closure. The coordinator owns any separately warranted
historical recovery decision.

The added evidence uses existing guarded actor metadata and contains IDs only.
Schema3, the eight-table layout, storage namespace and bindings are unchanged;
deployment needs no migration. Product/production integration remains with the root
coordinator. The source code and tests are ready for independent review.
