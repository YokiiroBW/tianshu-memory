## 目标与实现

新增两个显式操作，权限名与操作名一致，读写分离：

- `directory_scan`（权限 `directory_scan`，只读）：预览一个**配置登记**的目录。
- `directory_apply`（权限 `directory_apply`，写入，幂等）：确认一个本服务发给同一 client/项目/目录的预览。

目录必须由操作者在 `knowledge.directories.<project>` 中显式登记（`path`/`max_files`/`max_bytes`）；没有该段就完全不能扫描，目录不从项目根推断、不从调用参数放宽。`path` 必须是项目根内的相对子目录，不能是根本身、隐藏目录、`.git`、凭据/密钥/运行/模型目录，也不能经 `..`、盘符、符号链接或 junction 越界。

预览（`knowledge_plans`，带 source_revision 触发器）为每个候选固定路径、类型、大小、摘要和**当前索引版本**，并给出 `plan_id`（覆盖计划全部字段的指纹）、`omitted`（拒绝原因）、`missing`（已索引但当前不可扫描的来源及原因）、`counts` 与完整性标志。走查按名称排序、只列登记目录内相对项目根的 POSIX locator；符号链接/junction 不下钻不列出，被拒目录不下钻不列名，被拒文件只列路径与原因。单项 1 MiB 与登记的文件数/总字节只约束本次真正要写入的项：已是最新的文件照常列出但不占预算，所以重复预览仍能继续推进（不会因上一次导入而永久卡住）。走查上限 2048 条目，一旦截断或预算用尽，本次不产生任何 `missing` 候选——**漏扫和超预算永远不能当删除**。

确认必须原样回传预览。服务端在写任何内容之前校验：计划形状与自洽指纹（防篡改）、计划属于该 client/项目/目录、计划仍是该范围当前发出的预览（重新预览会让旧计划 `plan_superseded`）、项目登记与目录登记未变（登记收紧后旧计划 limits 超限同样冲突 `registration_changed`）。随后在事务外重读每个文件，逐项复核路径/类型/大小/摘要/当前索引版本：任一项变化的只成为该项 conflict（`source_changed`/`source_missing`/`source_too_large`/`unsupported_*`），**绝不把与预览不同的字节写进索引**；`version_conflict` 表示扫描后被并发手工导入改过内容或已删除，旧计划既不回滚也不覆盖；相同字节已是最新（含上次取消后已提交的项）记为 `unchanged`，不重复写版本。

每项一个短事务，`store.transaction` 的锁语义未改；所有文件读取在事务外，慢文件不占共享写锁（专项 gate 覆盖）。长任务在每次写入前重读配置授权与登记，撤权或登记变化立即失败关闭（已有的项保留，无操作记录）。项目行只在首次真正写入时创建，只读预览不为未初始化项目建行。计划本身持久保存，取消/重启后可继续。

删除策略 `explicit_approval_only`：`missing` 只是候选，只有把该 `document_id` 明确列进 `tombstones` 才写索引墓碑（版本+1、移出索引、项目 revision+1）；路径又出现记 `present_again` 且不删除，未列出的记 `not_approved`。本服务没有任何代码路径写入、移动或删除项目文件。

结果（`status`+逐项 outcome/conflicts/counts/remaining/rescan）持久记录在 `knowledge_operations` 与 `knowledge_imports`，可用原 key 通过 `status` 读回；同请求重放返回 `replayed` 的历史结果。该结果的失效沿用既有语义：目录导入增加项目 revision 与来源版本，因此旧 `recover` 包、`lesson_check` 和依赖这些来源的 `experience_check` 立即不再有效（与 URL、经验缓存失效联合验证）。

新增迁移 `migrate-directories`（单一负责人、显式备份、`knowledge_plans` 受 source-guard 跟踪）；`migrate` 在全新库中同一步安装知识+教案+计划三套表。未迁移的库对目录操作返回 `dependency_unavailable`（503），不会退化。CLI 新增 `migrate-directories` 子命令，`status`/`partial` 语义明确：`partial` 退出码为 1，不当作成功。可选 MCP 增加 `knowledge_directory_scan`/`knowledge_directory_apply`（读写标注分离），不监听文件系统、不轮询、不写任何客户端配置，也不自动全盘扫描。

## 限制、成本与下一步

1. `docs/candidates/project-directory-import/v1` 是本次新增的请求形状候选，根合同与 Hermes 真客户端交互待协调审查；计划指纹只做一致性与防篡改，不是授权令牌，授权仍来自配置登记与权限。
2. 目录扫描是显式一次性动作：无文件系统监听、无后台轮询、无全盘扫描；预览上限 2048 条目、256 项、8 MiB 每次，超出部分显式遗漏并要求重新预览分次推进。
3. locator 使用相对项目根的 POSIX 形式；同一文件若曾用其它分隔符手工导入，会被视为另一文档（除非它已被扫描并复用既有 locator）。文件名阻断规则不是内容 DLP。
4. 取消/中断后已完成项保留、结果不落库，但该键的绑定保留（`status` 为 `in_progress`）：同一请求可续做，换内容/换计划必须换 key。无跨进程任务队列、无进度流。
5. 仍是本地 SQLite 单写者、无大库吞吐承诺；目录导入会重读文件两次，慢盘代价与文件数成正比。
6. 未操作任何真实数据库、NAS 目录、Hermes 客户端或生产配置；未推送、未合并、未部署。

## 验收返修（2026-09-16）

协调裁决 `changes_requested`：并发同 client/key、不同 project/plan 时，两个请求都能越过初检，败者先写索引、最后才 `idempotency_conflict`（主 `docs/development/reviews/DSH-round3-2026-09-16.md` 的 TS-082 条目，P1）。

**复现**（本检出 `PYTHONPATH=src;tests`，`python -B -m pytest <主 .runtime/review-round3/test_memory_probe.py> -q -s`）：修复前 alpha 在 `observe` 挂起时同 key 完成 beta，恢复后 alpha 报 `idempotency_conflict`，但其两个文档已 `version=1, ready`，探针断言 `rows == {}` 失败——即“被拒请求已写入”。

**根因**：`directory_apply` 只在最终事务写 `knowledge_operations`，而它逐项提交发生在更早的独立事务里；幂等键在第一个副作用之前没有任何持久声明。

**修复**：在任何读文件与任何索引写入之前，把 `(client, key)` 与**该请求完整语义**（含 operation、project、plan、tombstones 的规范化摘要）绑定写入共享的 `knowledge_operations`（client/key 唯一权威），并在 `knowledge_imports` 记录 `in_progress`。`_replay` 改为“绑定感知”：摘要不同 → 立即 `idempotency_conflict`（对全部幂等操作统一生效，因此同键跨操作复用同样在写入前被拒）；摘要相同且仍是绑定（`$claim` 标记）→ 不作为结果返回，允许**同一请求续做/重试**；已完成 → 返回 `replayed` 历史结果。最终事务把绑定改写为真实结果（取消/中断后仍保留绑定，`status` 如实显示 `in_progress`）。绑定写入发生在 capture 短事务内（早于一切文件读取），慢 I/O 仍不持共享写锁；未改 `Store` 锁与事务语义。

**复现探针复跑**：冲突请求（同 key、异项目）现在在读取任何来源之前被拒——`idempotency_conflict` 抛在 `observe` 之前（读取计数不变），两个项目均零写入；持有该键的请求随后正常完成自己的项目。原探针文件把“败者”假定为**先发起**的那一个（旧实现由最终事务决定胜负），因此它对第二个请求没有 try/except，会在该调用处直接抛出拒绝异常、无法走到 `rows == {}`；其核心断言（“被拒请求不得写入”）由等价的修正探针覆盖并通过，二者都在交付包中：`.runtime/dsh-delivery/repro/`（复跑命令与输出见 `checks.txt`）。语义上胜负现在由**先绑定者**决定，这是让“拒绝发生在写入之前”成立的唯一可行顺序。

**正式回归**（返修后集中重跑，输入未变的检查不重复）：

- `ruff check .` / `ruff format --check .`（82 文件）/ `compileall`：通过。
- 专项：`pytest tests/test_knowledge.py tests/test_knowledge_transport.py tests/test_knowledge_concurrency.py tests/test_knowledge_directories.py -q --basetemp .runtime/tests-ts082-targeted` **89 passed**（目录文件 27 项，含 4 项新增返修用例）。

**迁移与备份说明**：本次修复**不新增迁移、不改任何表结构**——绑定复用既有 `knowledge_operations`（多一个 `$claim` 标记值）与 `knowledge_imports`（多一种 `in_progress` 状态），两者本就在 schema 3 + `knowledge_schema=1` 内并受 source-guard 跟踪。`knowledge_directories_schema` 仍为 `1`，已按首轮说明执行过 `migrate-directories --backup`（或全新 `migrate --backup`）的数据库无需再次迁移或恢复；未迁移库仍对目录操作返回 `dependency_unavailable`。上线仍要求停写、显式备份与恢复审查，未对任何真实数据库执行。
