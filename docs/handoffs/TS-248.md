## Changes

PG batches current source/group/projection reads and complete-candidate automatic
fact metadata. One native CTE statement ranks the complete authorized corpus using
the existing BM25 formula, replacing rowwise temporary inserts and repeated corpus
statistics. SQLite retains FTS5 and lazy source/body/projection/fact reads.

The real `SourceAuthority` PG barrier batches existing authority reads inside
`_apply` and skips strictly unchanged writes. It retains full receipt conflict
coverage, binding checks, same-sequence facts, all actor aliases, negative commits,
epoch changes, local CAS and guard order. Prefetched source rows observe physical
negative broadcasts before evaluating current admissions. Fresh metadata read
after the lock shares PG marker/checkpoint work, reducing five reads to two per
transaction. SQLite's SQL path is preserved. No grant survives a transaction.

Knowledge reuses leased Store resources across direct/MCP calls and HTTP request
applications. Configuration/auth are reread per phase; a registration change retires
resources and a mid-dispatch change fails. Private per-dispatch fields, source file
double reads, verified FileRefs, revision/seal checks, final transactions, timeout
admission ownership and late-worker completion remain. PG ranked rows carry their
current citation proof, eliminating three extra SQL reads per block per phase.

Design and comparison procedure: [pg-read-performance.md](../pg-read-performance.md).

The narrow follow-up `5a934bc` keeps full authorized corpus size/length/DF, but
joins only relevant term frequencies into the final PG BM25 aggregate. Its left
join retains zero-score hits. SQL returns ID/score; the current-call Python corpus
supplies the exact input text. PG lineage returns only the seven columns used by
both authority paths. Legacy select and memory-context query explicitly reuse one
raw/decoded automatic-fact snapshot during their current select transaction; new
verification transactions retain fresh reads. SQLite SQL/lazy reads and Knowledge
snapshot logic were not changed. Shared 0.1.1/vendor/pin and Q15 ancestry integration
remain the coordinator's subsequent exclusive work.
