## Behavior

`fact_entities.resolve` now reuses the existing source-backed entity matching path
for a color-only cup subject such as the second clause in
`蓝杯子现在改叫细雨，红色的还是晚霞。`. Its own full evidence quote must contain
the adjacent explicit cup naming clause. A short quote, separate sentence, book
context, third-party subject, question or hypothetical cannot supply that noun.

The current scope's existing valid facts remain the only entity source. Color
matching deduplicates entity IDs across properties, requires one grounded match,
and counts unfamiliar same-color materials or qualifiers as possible conflicts.
For example, `红玻璃水杯` plus `红磨砂水杯` is ambiguous; `红茶杯子` alone cannot
prove the color red. A supplied entity ID must equal the unique match. Ellipsis
cannot create an object, bind another scope or revive a forgotten object. Original
proposal mentions and evidence quotes are not rewritten to invent a cup noun.

The complete blue correction plus red reaffirmation commits atomically. The red
reaffirmation is retained, including its `automatic_evidence`, lineage and latest
`observed_at`. Existing automatic-fact merging and ordering already provide the
required result for T0=A, delayed T1=B, T2=A in both commit orders; no parallel
ordering implementation was introduced. An undated reaffirmation keeps an existing
effective interval while adding its new observation and evidence.

`CandidateExtraction` now reads the same-job committed ledger through one local
helper. After a semantic `invalid_input` rolls back the current proposal, it checks
the ledger before returning `rejected`. A null-output lookup also checks within
its existing `MemoryService.operation` before returning `pending`. Thus an older
request that commits while `_content` reads and masks the already-consumed source
returns the original completed receipt. Publisher ownership checks remain before
receipt access; the new reads add no network transaction, queue or global lock.

## Limits and next step

These results establish local SQLite and synthetic-owner behavior, not native
PostgreSQL, deployed products, real model quality or the coordinator's final Q17
storage overlay. The coordinator owns final frozen-contract/overlay verification,
UUID-isolated PostgreSQL replay and actual model acceptance. This contributor made
no PostgreSQL, Redis, NAS or model connection, read no credentials, and did not push,
deploy or update root/shared task records.

The reconcile closes the proved window where an older same-job result is already
committed and visible at the decision read. A still-in-flight request that has not
yet committed remains unknowable at that instant. `rejected` describes the current
proposal; it is not a promise that another request for the job can never commit.
Color handling deliberately covers the proved adjacent cup-naming pattern rather
than general Chinese coreference or arbitrary object kinds. Integration and wider
acceptance remain the coordinator's responsibility.
