## 结果与复用

`observation_actor_sources.py:ObservationActorSources` 是原被动观察 owner 的窄端口；actor domain 不直接打开用户 Store。`ObservationLedger.read_exact()` 在已有 guarded snapshot 上核对归档原包、事件 digest、native frame、scope version、archive epoch 和原文；持久原包损坏返回 unavailable，不当成调用方错误或新事实。

来源 descriptor 已与 TS-386 锁定：

```json
{
  "producer": "observation",
  "object_id": "<原 source_ref>",
  "revision": "<scope_version>:<archive_epoch>",
  "content_hash": "<原 source_digest>"
}
```

revision 为两个正整数的十进制、无前导零。event.revision=1 由原归档 owner 校验，不由调用方添加新事实。

事实固定为 `observer / observation / observed`，occurred_at 取原事件 sent_at，learned_at 取实际归档 received_at。summary 为固定观察说明与最多 3900 字原文片段，不证明 bot 已发言或已经理解。`content_reads=[]`：没有伪造阅读 coverage、完成观看或数字行动。原群约束取 Platform 原 segment channel 经 Core 原 learning-frame 映射的 conversation ID，不能使用调用方自报的 native 群号代替。

复用原 `segment_sources.check_platform()` 的 Memory→Platform segment verifier、`check_frame()`、精确 aliases/suppression 和来源状态。已有 Core alias 的实际 current 检查复用 `SourceAuthority._checkpoint_observations()` 的 facts/current/head **只读采集半部**，不调用 apply、barrier commit 或用户业务 operation；可在用户 source head 尚未更新时发现 Core 新撤回。没有用户 material/source 投影不等于撤回，原 raw archive 已受理即能形成角色观察，**不依赖 automatic_memory_candidates 或用户提取后台**；不为此创建用户材料、person、turn、候选或摘要。

`actor_memory/authority.py` 对 producer=observation 委托该端口，其他 producer 的原固定 HTTPS owner 配置与请求行为不变。来源 query/get_episode/check_episode 继续经过原 actor application 的前后来源核验、事务、receipt 与派生失效逻辑；append 的 relation 必须为 observer。

## TS-386 模型前后只读接口

新增 `POST /internal/v1/actor-self-memory/observation-source`，直接复用冻结 `source_facts_request/result` 或 `source_check_request/result`，仅接受 producer=observation，source_check 仅允许 actor_only context。

- 仍使用原 actor-memory caller、allowed_actors / allow_runtime_roles、原 admission/body/lease。
- source_facts 映射 caller 既有 query 权限，source_check 映射 check_memory；前后均由 Platform 当前 role_version / memory.read 权威复核，并重新验证 caller。
- 不扩大 token、Platform service 身份或浏览权限；不先 append 所有原话来获取 episode ID。
- response 精确回传 request_id/actor_id/source。source_check 的 version 三元组为 `source_generation / source_sequence / access_version`；generation 为 `observation:<archive_epoch>`，sequence 为原 scope_version，access_version 为当前精确 proof 的摘要。
- TS-386 应在模型前后核同一 descriptor、current/read_allowed 和完整 version 三元组。facts 来源失效返回 not_found；check 返回 missing/withdrawn/superseded 的否定。transport/暂不可用返回 dependency_unavailable，不得转成永久 forget。
- 只读口不写 episode 或 actor receipt；有价值观察仍由 TS-386 原 actor outbox + append_episode/get_receipt 持久化。

## 历史与新自动工作边界

历史读取只用原 archive/read/actor 绑定权威，停止观察不等于删除历史。该端口不把 participation 候选 TTL 当来源有效性，不要求主动发言权限，也不开放回复。停止、新群 processing、off/on 与 A→B→A 晚包的 per-group generation 由 TS-386 在实际新判断/沉淀/探索每阶段处理，不能仅比较当前 actor 字符串。

原 source/suppression、真实 alias、archive epoch、精确 actor 绑定否定会使 actor episode 与 derived 不可用；一旦原 actor application 已确认失效，恢复配置或晚写不能复活旧 episode。临时 transport 失败只阻止当前读取，不自行永久 withdraw。原 archive 行不删除。
