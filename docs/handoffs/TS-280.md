## 问题与结果

既有 `named_reference()` 只识别“阿川的／阿川那只／阿川家的”等形式。
“阿川上次提过的那只猫叫什么来着”没有进入具名来源连接，可能退到普通群猫主题召回，
没有把当前唯一、来源已证明的姓名事实作为完整见证带给调用方。

本卡扩展同一解析函数，识别确切 canonical 姓名后紧邻的有限“提过／提到过／说起过／
说过＋的”结构，支持其前的“上次／之前／以前／刚才／前面”披露时间词。
既有 `named_owner()` 继续在已经授权的同群候选中证明当前姓名唯一性，并返回该来源作者的
候选与完整姓名见证。返回原记录、原 statement 和原来源，不重写事实或推断实体归属。

“阿川提过”只限定消息来源作者；它不证明对象属于阿川。“阿川家的”仍使用原 possessive
分支。本卡没有将来源作者 ID 转换为宠物真实拥有者。

仅消耗修饰披露动作的时间框架，保留对象本身的全部原始剩余文本。真实 selection 用例验证：

- “阿川以前提过的猫现在叫什么”只返回当前栗饼和阿川姓名见证，不返回旧栗团或小禾的栗糖。
- “阿川上次提过的猫以前叫什么／原名是什么”保留旧事实；“以前那只猫”“以前的那只猫”
  的对象限定也未被吞掉。

新来源分支复用既有 topic/query/object 词汇识别对象开头，不另建 NER 或第二套主题词表。
它不跨内部标点、引文、否定、条件、多人或第二拥有者进行正向连接。已识别但不支持的来源
结构返回空 reference，`named_owner()` 明确返回空候选及空见证，避免删掉限定后泛召回别人的猫。
“阿川提过的那只”等空对象通过真实 query 验证不崩溃。

## 复用的保护与限制

既有完整窗口、当前唯一姓名、人物 scope、完整语义组、整组 lineage、source freshness、
姓名见证与目标一起 fit，以及外部 I/O 后重新证明来源和姓名当前性的路径不变。
现有 duplicate/truncated-window、fit、source/grant/witness 撤回、姓名到期／同名生效／新姓名
写入用例都增加了本次来源形式参数。原私聊、异群和 actor 隔离用例也在同一群组件中运行。

覆盖为有限自然句式，不是全语言理解。未建立唯一 canonical 姓名来源、未知别称、复合转述、
引文或有限对象词汇以外的目标不保证可连接；没有为评测名字补造姓名事实。
“阿川提过的小禾家的猫／别人家那只猫”明确不把它替换成阿川自己猫的主题结果。

已有 `query.py` 的显式 self-reference 先于具名来源路由。因此
“阿川提过的我家的猫”仍按请求者自己的 scope 处理，真实用例只返回请求者的雪球，
不把这个结果冒称为“已证明阿川提过”的来源连接。本卡没有扩大该既有路由的职责。
只返回原始 statement 及来源；调用方仍须据原文区分转述中的对象拥有者。
