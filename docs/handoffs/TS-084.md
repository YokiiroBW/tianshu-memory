## 目标与实现

**七个操作**，权限名与操作名一致并分别授予：`note_record`、`note_revise`、`note_withdraw`、`note_query`、`note_recover`、`note_status`、`note_check`。加入 `PREVIEW` 之外的普通读集合；写操作进入幂等集合。缺少操作权限时在读取任何项目数据之前 `forbidden`；错凭据 `unauthorized`；未在客户端 `projects` 内的项目 `forbidden`。

**六类内容分开。** `question` 是研究问题；`source_statements` 是来源论述，每条的 `statement` 是操作者自己的话、`source` 是**实际读到的**已登记资料版本与完整语义单元引用；`inferences` 是研究推论；`open_questions` 是未决问题；`decision.summary` 是项目决策；`decision.basis` 是决策依据。`decision` 必须显式给出非空 `basis`，依据是资料单元（`kind="source"`）或另一条已记录的笔记版本（`kind="note"`）；没有依据的决定 `evidence_required`。**模型建议、推论文本、来源标题、摘要字符串都不能充当依据或引用**：引用只接受与 `query` 当前返回一致的块引用（`block_id`/`document_id`/`version`/`hash`），跨项目块引用即使调用者能读两个项目也被拒绝。来源正文从不复制进笔记（用例断言原文不在笔记规范化输出中）。

**身份与版本。** `note_id = "note:" + fingerprint([project_id, key])`，版本从 1 起。身份只创建一次：重复录入是 `version_conflict`（声明版本先于身份检查，与项目自身 `import` 的次序一致），同负载重放返回历史结果，异负载 `idempotency_conflict`。`note_revise` 复用同一 `key`（否则 `identity_conflict`）、要求 `expected_version` 等于当前版本，追加新版本并**替换**整个版本内容（未给出的字段不继承）；旧版本连同它的引用行原样保留，`note_status` 可按版本读回。`note_withdraw` 追加带 `withdrawn.reason` 的版本、让笔记离开检索索引、使引用它的决定不再可复现；撤回后不能修订回活（`already_withdrawn`），不能重复撤回。只有记录该笔记的身份（`research_notes.owner` 对 `application.client`）可以修订或撤回（`forbidden`），同一项目的其他身份可以读取。

**引用状态在读取时推导，不改写历史。** `live`（单元仍是记录时的版本与内容）、`expired`（file 变化/删除、文档墓碑、URL 快照刷新到新版本）、`note_unavailable`（被引笔记撤回、被修订到新版本或自身引用已过期）。过期引用只返回状态与坐标，**不返回正文**；项目不再登记某 URL 时该项目所有操作以 `registration_changed` 失败关闭，不返回缓存结论、也不改写笔记与引用行。`note_query` 的每条笔记都带完整 `citations`（序号、种类、坐标、状态）与 `citation_states`；`current` 是"该版本所有引用都可用"的派生结论，因此旧结论始终可追溯，同时不会被静默重新标为当前。

**循环拒绝。** 决定依据引用另一条笔记版本形成引用图，写入前遍历：自引、二元环、以及**超过 `MAX_CITATION_DEPTH`（64）的链**都以 `citation_cycle` 失败关闭——不是"走到上限就接受"，因此环无法藏在上限之外。一条结论永远不能成为它自己的证据。

**三阶段事务。** 捕获段只做本地读取并把每个要核验的资料单元记录成期望（`SourceContext.observe`），**不做任何文件 I/O**；外部段在事务外读取证据；提交段用短事务比较记录结果并提交。慢来源不占用共享写锁，文件在两段之间变化一律判为过期。读取操作也走同一形状：捕获段记录它看到的单元（包括已经过期、必须如实描述的那些），提交段据此回答，所以"来源刚被改写"的读取返回 `expired` 而不是把整次读取判成失败，也不会把所有引用都误报为过期。

**字节预算。** `note_query` 的 `text`/`budget_bytes`（256–32768）；一条笔记连同它的全部引用是不可分割单元，装不下就整条省略并计入 `omissions=["budget"]`，**从不返回只有部分证据的笔记**；预算连空结果都放不下时 `budget_too_small`，不截断。`note_recover` 预算 1024–32768，返回同一批笔记加 `goal`/`unfinished` 与 `revision`/`registration`/`seal` 的短包；`seal` 绑定 client 凭据摘要，另一个 client 无法校验他人的包，`note_check` 按固定顺序裁决（`stale_or_tampered` → `registration_changed` → `revision_changed` → `note_changed`）。`retrieval` 恒为 `lexical`：没有向量、没有模型、没有假成功；只含脚手架词的查询没有主题，因此没有候选。

**接续边界。** 笔记是独立的有界只读结果：`continuation_recover` 不被笔记模块反向控制，笔记也不注入工作目录事实——`note_recover` 不含 `worktree`/`branch`/`head` 等字段，`project_workdir` 恒为 `authoritative_over_notes`。

**迁移。** 新增 `research_notes_schema=1` 元数据标记；表 `research_notes`、`research_note_history`、`research_note_citations` 全部注册 `source_revision_*` 触发器（`research_note_index` 为 FTS 派生索引，与其他域一致不入跟踪名单）。全新库由 `migrate` 在同一已审查步骤内安装；已有库用 `migrate-research-notes --backup <不存在的路径>` 显式升级（要求 `schema=3` + `knowledge_schema=1` + 无笔记标记），迁移前完整数据库保留在备份路径，已升级库再次迁移被拒绝。缺少标记时所有笔记操作以 `dependency_unavailable`（503）失败关闭。不重建、不覆盖 schema 3 检查点。

**入口。** CLI 新增 `migrate-research-notes` 子命令，MCP 新增 7 个工具（服务共 25 个）；两者只做参数、身份与错误映射，调用同一个 `application.execute`，都不直接 SQL。

6. 项目与身份：跨项目不可见（`not_found`）、跨项目引用拒绝、同项目其他身份可读但不可改（`forbidden`）、撤权后 `forbidden` 且不泄露是否存在、恢复权限后笔记原样返回、无笔记权限的读取者被拒绝。
7. 版本与幂等：`version_conflict`、`identity_conflict`、`already_recorded`、`already_withdrawn`、同负载重放、异负载 `idempotency_conflict`。
8. 重启持久化：修订后的当前版本、历史版本与历史引用在重启后原样可读，`note_check` 对旧包给出 `revision_changed`。
