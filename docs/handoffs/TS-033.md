## 交付行为

schema 3 拆分 P 当前事实/物理墓碑与 A 来源、lineage、source_writes、候选快照及 suppression。旧来源仅按已证明完整 scope/画像批准迁移，保持未核验；歧义原子回滚，旧 withdrawn 只抑制被证明 A，不伪造 P 墓碑或 owner 回执。旧确认缺 binding_version，不能用于生产 revise。

真实 `SourceTransport` 连接固定 Core facts 与 Platform current HTTPS，证书完整验证、独立可撤销凭据、禁重定向/环境代理，严格 JSON、响应关联及 1 MiB 限制。实际认证与本地 binding/时钟/事务核验由产品承担，发布包 rules 只做关系断言。

`SourceAuthority` 在 select/profiles 零预算、consume、候选提交、revise、后台 check 前执行 m0/完整 coverage → C1/P1/C2 → 独立失效提交 → 业务事务再比较 revision。网络期间不持有 SQLite 写锁。完整 owner event/turn/input_sources/分类核验支持 owner 证明的 aggregate 跳号；拒绝缺项、伪 event/reality、同 P 多修订、回执别名和未证实归档。两个 owner 水位及逐 P/A/turn/access 观察持久化，拒绝回退、generation 改变及同水位异事实。

P 否定在一个事务影响全部本地 actor 血缘；A 撤权/correct/forget 只影响本 A。公开/群 epoch 仅在活动共享投影首次失效时同域推进一次；画像 coverage 包含当前 actor 所有活动公开/当前群来源，跨作者、空目标和零预算均不能绕过。失效删除可检索索引；随后 409 不能撤销已提交否定。

已接入正式 `POST /internal/v1/memory/source-sync/check`，配置操作名 `check_sources`；身份 resolve/register 仍不调用来源同步。`memory.sync` 为进程内受信编排，无任意 observation HTTP 写入接口。`TrustedWorkflow` 与 fixture 分开，共享现有 SQL 写入逻辑，候选严格范围与 A 去重，确认绑定完整操作/账号/scope/binding/record/version/有效期且一次消费。没有真实用户批准适配器时确认不可用，模型或 token 不能签发。

## 迁移、恢复与缺口

命令、配置、备份/异常/恢复流程唯一入口为 [来源同步运行说明](../source-sync-runtime.md)，项目 AGENTS/README 已补充真实验证命令。

source-guard 是数据库备份之外的检查点，用于**检测回退并拒绝**，不会恢复丢失 suppression/ledger/outbox。受信部署可指定 `source_sync.recovery_path`；默认数据库旁 sidecar 仅是独立文件，不是独立故障域。正常重启、缺失/损坏检查点、旧 DB 恢复、检查点写后数据库提交前中断均已验证；中断可能使检查点领先，记录明确本地诊断并保持不可用，不能自动解锁。

**旧 DB 与旧 guard 同时回退无法检测**，测试明确展示此不支持恢复方式可以重新出现旧记录。此边界不能记作通过恢复验收，也不能靠把旧库自报 ready 当恢复证据。保留最新检查点和完整权威账本，在全部服务停写后另行审查恢复完整性；本任务不提供通用恢复审批、重建或生产恢复操作。
