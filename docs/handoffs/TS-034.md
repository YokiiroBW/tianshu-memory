## 交付行为

- `user-action` CLI / `LocalUserApplication.execute` 将执行完整操作文件视为明确操作。独立用户 token 通过环境传入，仅在部署配置存摘要；稳定账号、actor、revision_scopes 与精确 profile_permissions 均由部署者登记。实时平台 HTTPS resolve 后核对 Memory binding，业务写入前重读用户登记和绑定版本。服务 token、自报 verified_context/confirmed、任意返回 True 的适配器不能签发批准。
- 遗忘继续使用正式 `sync-workflow#confirmation_input` 和旧 HTTP revise。完整语义摘要、record/expected_version/account/scope/binding/期限绑定；一次消费和同 HTTP 幂等重试保持。SourceAuthority 远端失效先提交；A 的遗忘/更正不删 B，不删物理消息。correct 保持仅禁旧值、不生成可读 replacement。
- 画像共享原 `profiles.validate_draft` 和完整组发布 SQL。真实批准另外持久化操作主体、账号绑定版本、精确草稿、来源快照和登记权限摘要；发布前全部重验。owner 仅本人的 interest；person style、group topic/style 需该群精确 curator 权限；可从该群其他成员来源整理，不可用此权批准他人兴趣。本人可明确共享私密兴趣到当前群；public 仍只本人 interest。旧 group_only 批准不能升级公开。
- `revoke_profile` 持久撤销待发布或已发布批准。已发布整组失效并推进对应共享 epoch；重试不恢复。新表的单独待发布撤销也受 guard 跟踪，旧数据库恢复不能抹掉撤销。群撤销不推进无关私密/公开 epoch。
- `migrate-users --backup` 是 schema 3 上显式加法迁移（local_users_schema=1），加入 profile_approval_authorities 及变更触发器；不改变跨产品版本。保留含 WAL 的新路径备份，错误事务回滚，guard 提前持久化后故障继续失败关闭。完整恢复/降级限制见运行说明。

1. 尚未集成，不能宣称完整 L0 通过。TS-050 基线确认503/无确认forget403/画像503和已有10个联合场景证据不变；协调者审查合入后，使用新本地配置与迁移另跑真实三方正向验收。
2. 本地配置、操作文件、数据库访问及调用应用代码属于 OS 信任边界。仅支持本地 CLI/同产品受信应用；不提供网页登录、远程操作接口、自动同意、泛化审批平台或生产部署。用户独立随机 token 要由部署者安全提供。
3. 当前权限登记可复用，但不是自动批内容。批准/发布每次显式执行完整草稿。配置变化阻止后续发布；已发布内容需明确 revoke，配置不是后台自动回收机制。
4. 撤销仍要求当前认证、对应权限和远端来源屏障可用；不能在远端故障时宣称成功。缺配置/缺画像迁移保持503；无界全库索引重建仍不可用。
5. guard 只能检测数据库与独立检查点不一致，不能识别两者同时回退到匹配旧版本；没有恢复批准/重建/解锁工具。迁移完成后保持最新数据库/WAL/guard/批准消费和撤销账本，不直接恢复迁移前备份、不删新增表降级。
6. 来源容量、SQLite/WAL、PostgreSQL/嵌入未接及 correct 不补新值等边界沿 TS-033。两个第三方弃用警告保留，不以改锁消除。
