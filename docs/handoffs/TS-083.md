## 目标与实现

新增两个**只读**操作，权限名与操作名一致并分别授予：`continuation_recover`（生成接续包）与 `continuation_check`（复用前重新观测并裁决）。两者都绑定身份、项目与目标 worktree，`seal` 绑定 client 凭据摘要，另一个 client 无法校验他人的包。

**登记是唯一入口。** 检出必须由操作者在 `knowledge.worktrees.<project>` 中显式登记（`id`/`path`/`branch`/`clients`/`files`/`max_bytes`）。未登记与属于他人同样返回 `worktree_unregistered`（403），不泄露他人是否登记检出；`path` 必须是绝对路径、存在、且**自己是检出根**（子目录 `workdir_not_root`、非仓库 `workdir_not_repository`、不存在 `workdir_unavailable`）；任意层级不得是凭据/密钥/运行/模型/构建目录（允许点目录）。登记段畸形时 `write_state` 失败关闭（`invalid_configuration`），有意的取舍：宁可不写，不猜。

**可信本地只读采集器**（`knowledge_workdir.py`）固定 `argv` 形状：`git -C <path> --no-optional-locks -c core.fsmonitor=false -c status.submoduleSummary=false -c log.showSignature=false <只读子命令>`。允许的子命令集合与调用顺序都被测试断言：`rev-parse --show-toplevel`、`rev-parse --verify --quiet HEAD^{commit}`、`symbolic-ref --short -q HEAD`、`status --porcelain=v1 -z --untracked-files=normal --ignore-submodules=all`、`log -n 8 …`、`--version`。

- 没有 `fetch`/`checkout`/`reset`/`clean`/`diff`/`pull`；不联网、不进子模块、不执行仓库配置的 helper（真实 fsmonitor 钩子用例证明钩子没被运行）、不读 diff、不读未跟踪文件正文、不列脏文件路径（只给 `staged`/`modified`/`deleted`/`renamed`/`untracked`/`conflicted`/`entries` 分类计数）。
- 有界：单次 10 秒超时、status 输出 256 KiB、log 64 KiB、`--version` 256 B、历史最多 8 条、登记文件最多 16 个、单项摘要 1 MiB、登记总字节 ≤ 8 MiB；超限是明确错误（`workdir_timeout`/`workdir_output_too_large`），不静默截断。Git 缺失或不可执行 `git_unavailable`（503）。
- `GIT_OPTIONAL_LOCKS=0` + `--no-optional-locks` 保证不刷新也不写索引（用例断言 `.git/index` mtime 与 `HEAD` 字节不变）；宿主系统 Git 配置**故意保留**，这样采集结果与编码体自己的 `git status` 一致（早期去掉系统配置会因 `core.autocrlf` 差异误报 modified，已修正并留下对照用例）。
- `status` 前后各读一次 HEAD，采集期间检出移动即 `workdir_changed`，绝不报告半新半旧。仓库文本按不可信数据处理：去控制字符、200 字符截断。
- 采集发生在两个短事务**之间**：慢 Git/磁盘 I/O 不持共享写锁（gate 用例：采集被挂起时同一 Store 的真实 `MemoryService.register/resolve` 仍在 1 秒内完成）。`git.writes` 恒为 `never`；包不回声宿主绝对路径，也不含凭据。

**三层事实严格分开呈现**，因为它们的可信度不同：

| 段 | 内容 | 是否本次实测 |
| --- | --- | --- |
| `worktree` | 期望/实际分支、detached、`head`、unborn、脏状态分类计数、登记文件当前摘要与状态、Git 版本/上限/允许子命令 | 是 |
| `history` | 最近 8 条提交（`commit`/净化后的 `subject`/`committed_at`），达上限 `complete=false` | 是，但只到上限为止 |
| `index` | 已索引文档 `document_id`/版本/状态/存储哈希/`freshness` | 否 |

`freshness` 只有 `verified_current`/`verified_changed`/`unverified` 三种：**未登记摘要的索引行永远不声称是当前文件**，旧摘要与当前摘要并排展示、互不覆盖（用例：改写未提交文件后 `verified_changed`，而 `worktree.files[].digest` 给出当前字节摘要）。登记文件缺失/不可读/超限是诚实状态（`missing`/`unreadable`/`too_large`）；登记路径若变成越界链接或不支持类型，整次接续失败关闭。

**验证绑定。** `write_state.recent_verification` 接受纯字符串（旧形状，永远 `unbound`）或 `{summary, worktree, commit}`；结构化条目由服务端在写入时盖上**实际观测到**的 `commit`/`branch`/`dirty`/`declared_at`。声明一个并非当前 HEAD 的 commit 立即 `workdir_conflict`（409）且零写入——**历史测试结果不能冒充当前提交的测试**。读取时按本次实测重新标注 `scope`：`current`/`historical_commit`/`workdir_changed`/`other_worktree`/`unbound`；一次状态写入最多绑定 4 个不同检出（`too_many_worktrees`）。

**`continuation_check`** 原样回传包并给出 `valid`/`reason`/`differences`/`observed`，命中顺序固定：`stale_or_tampered`（seal/项目/项目登记指纹）→ `registration_changed` → `revision_changed` → `index_changed` → `branch_changed` → `head_changed` → `workdir_dirty` → `file_changed` → `stale_evidence`。切分支、新提交、新未提交改动、索引或 revision 变化都使旧包失效；工作目录整体不可观测时返回 `observed=false` 的裁决而不是静默成功（`recover` 在同样条件下失败关闭）。撤权、移出项目、错凭据在任何读取之前就 `forbidden`/`unauthorized`。

**字节预算**不伪报：`budget.used_bytes` 等于返回包规范化后的 UTF-8 实际字节数（用例断言相等），`unit=utf8_json_bytes`；装不下的可选资料单元整单元丢弃并记 `omissions=["budget"]`（从不切半）；必读部分（工作目录事实、历史、索引、已声明状态）从不切分，装不下时 `over_budget=true` 并仍返回完整状态。没有 tokenizer，因此 `tokenizer=null`、`token_counts=unavailable`。

**复用而非另造**：包内资料单元复用 `recover` 的 `_query`/`_reference`/`_seal`，索引段复用目录索引用到的索引表与 `FileReader` 规则，状态段复用 `write_state` 的权威与版本语义；`continuation_recover`/`continuation_check` 加入既有 `PREVIEW_READS`，因此未初始化项目也能读，且**只读预览不创建项目行**（与目录预览一致）。CLI 与 MCP 各加一条显式操作/工具（共 22 个工具），MCP 标注只读。

`tests/test_knowledge_continuation.py`（31 函数 / 48 用例）覆盖：

1. 登记段逐字段校验（缺字段、类型、id 形状、绝对路径、`..`、凭据/运行目录、`files` 名称与扩展名、越界 `max_bytes`）在任何路径被读取之前拒绝；重复 `id` 拒绝。
2. 无登记段时完全不能接续（`worktree_unregistered`），而旧形状的状态写入仍照常工作（`verified_worktrees=[]`）；未登记与属于他人的 worktree 一律同样的错误码。
3. **两个编码体各自登记自己的检出**：同一项目、两个 client、两个检出分别接续，互不可见、互不干扰。
4. 子目录（`workdir_not_root`）、非仓库（`workdir_not_repository`）、已消失（`workdir_unavailable`）分别拒绝。
5. 采集结果与检出自己的 `git status` 逐项一致（脏前后、分支、HEAD）。
6. detached HEAD 明确 `detached=true`+`branch=null`；未出生分支 `unborn=true`+`head=null` 且历史为空。
7. 历史有界（9 次提交只列 8 条、`complete=false`、最新在前）、控制字符被去掉。
8. 包分层：`history`/`index`/`worktree` 三段并存且 `seal`/`revision` 可追溯；包内不含宿主绝对路径。
9. **索引摘要不覆盖当前文件**：改写未提交文件后 `index.freshness=verified_changed`，`worktree.files[].digest` 是当前字节；未登记摘要的文件永远 `unverified`。
10. 状态写回目标/约束/下一步/结构化验证，并盖上观测到的 commit/branch/dirty；声明非当前 HEAD 的 commit → `workdir_conflict` 且零写入。
11. 一次写入最多绑定 4 个检出。
12. 历史/移动过的验证永不显示为 `current`：HEAD 前进 → `historical_commit`，脏状态变化 → `workdir_changed`，绑定另一个已登记检出 → `other_worktree`，旧字符串 → `unbound`。
13. 预算：`used_bytes` 等于实际 UTF-8 字节数、越界预算 `invalid_input`、必读部分不被切分（`over_budget=true` 且状态完整）、装不下时整单元丢弃并记 `omissions=["budget"]`、`tokenizer=null`/`token_counts=unavailable`。
14. **只读**：不建项目行、不建文档、项目 revision 不变、`.git/index` mtime 与 `HEAD` 字节不变；未初始化项目也能接续（`revision=0`、`state=null`、`index` 为空）且仍不建项目行。
15. `check` 跟随真实事实：切分支 → `branch_changed`、新提交 → `head_changed`、新未提交改动 → `workdir_dirty`，`differences` 顺序稳定。
16. 索引/revision 漂移（外部导入、删除文档）→ `index_changed`/`revision_changed`。
17. **身份绑定与撤权**：换 client、换凭据、移出项目、改动包任一字段 → `stale_or_tampered`/`forbidden`/`unauthorized`；项目未迁移 → `dependency_unavailable`。
18. 检出整体不可观测时给出 `observed=false` 的裁决（另一检出仍然正常接续）。
19. 仓库配置的 fsmonitor helper 从未被执行（钩子标记文件不存在）。
20. 只读子命令集合与固定参数被断言；远端前进后不 fetch（远端跟踪引用不动）；不出现 `diff`/`checkout`/`reset`/`clean`/`pull`。
21. Git 失败/超时/输出超限/缺失分别失败关闭（`workdir_git_failed`/`workdir_timeout`/`workdir_output_too_large`/`git_unavailable`），且失败不落成“部分观测的检出”：无法回答身份调用的 Git 在 `check` 侧也给出 `observed=false` 的裁决，恢复真 Git 后同一包重新有效。
22. 慢 Git gate：采集挂起时共享写锁不被持有。
23. 越界（junction）登记文件与超限/缺失登记文件的诚实状态；未登记摘要的索引文档永远 `unverified`（只展示存储哈希，绝不冒充当前文件），且包内任何字符串都不含宿主绝对路径。
24. 未迁移库（缺 `knowledge_schema`）对两个操作都 `dependency_unavailable` 且不改动任何行。
25. 真实 CLI 子进程与官方 SDK stdio 全链（`tools/list` 22 个工具、两个新工具可调用、他人包/他人 worktree 在 MCP 侧同样被拒）。

## 限制、成本与下一步

1. 未做跨检出比较：`other_worktree` 只标注归属，不判断对方 HEAD 是否等于其声明；两个编码体各自接续即可，协同语义待协调者定。
2. `index` 段中未登记摘要的文档永远是 `unverified`——本服务只核验返回的资料单元与登记摘要，不重读整个索引，因此不承诺大库吞吐。
3. 历史最多 8 条、登记文件最多 16 个、脏状态输出最多 256 KiB；超限明确报错或 `complete=false`，无分页续读。
4. 分支名、`path`、`files` 都属于登记内容：登记收紧或变化会让旧包与旧验证绑定失效/冲突，需要重新接续；这是有意的失败关闭，不是兼容性缺陷。
5. 仍是本地 SQLite 单写者，无后台任务队列、无文件系统监听、无轮询、无跨产品 HTTP；接续只在调用时采样一次。
6. 未操作任何真实数据库、真实仓库、Codex/Hermes 配置或生产服务；未推送、未合并、未部署、未触发下游任务。
