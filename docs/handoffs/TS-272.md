## 实现归属与兼容边界

`fact_names.py` 统一有限谓词 `identity.name/person.name/author.name/name` 的本人姓名
来源证明与事务内读取视图。只接受 `entity=null`、实际作者、real、无条件/否定且证据支持
的姓名；名称仅用于已授权范围内的相关性与真实 owner 连接，不授予 scope。

- `candidate_extraction` 在原始 evidence 精确子串和来源时间验证之后调用同一规则，
  在 `field_key/target_key`、摘要、合并之前统一为 `identity.name`。新 canonical 草稿
  也必须通过同样证明，不以 key 自证正确。保留 value 内引号和原始 quote；只有本人
  姓名 proof 从本服务已经读取的 `_content` 附带完整 `source_text`，模型不能提供该字段。
- `automatic_facts` 复用该视图进行 known/current、重申与更正；新旧拼写在一个当前
  family 内比较。相同值走原重申，不同值沿既有 `_supersede`；源时序仍决定新旧。
  读取不重写旧行的 `fact_key/payload.key/groups.field_key`，没有旧事实补写或重抽。
  原文证据不全的旧组不参与姓名 merge；新自报另建有完整证明的 canonical 组。
- `fact_queries/fact_references`、legacy select、PG exact、context query 和
  `recall_relevance.named_owner` 复用同一 current/family/field 语义。有限旧键是候选 hint，
  只有完成原完整组/来源/owner 校验及每条完整原文边界证明后才作为 canonical 姓名。
  这里的跨键兼容仅适用于有真实原文证明的记录，不代表旧 9 条别名已被自动修复。
  普通非姓名 field/item
  保留原单值 `=` 查询和原事实语义，不为姓名读取扫全库。
- 同一 owner 的有限姓名 family 统一有界最多 128 条；SQL 取 128+1 并标溢出。
  群路径沿原 4096 完整候选组域，所有姓名 category 参与唯一性，截断不能据前缀判唯一。
  相同生效时点且不同值不择一；失效、未生效、冲突或不完整姓名不能降级为精准 owner 答案。
  已授权完整域中有限 raw 姓名形状的精确字面 hint 只拒绝不确定归属，不能选 owner。
  同 owner 新 fresh 姓名可覆盖自己的旧 NULL 同名未知项；另一 owner 同称呼未知则保守。
  普通无姓名的群事实提问仍正常召回，不自动补出缺失整条姓名事实（包括旧 g02）。
- family metadata、原整组、lineage/evidence 使用集合分批读取；没有逐 owner operation、
  新身份目录、额外 RPC/模型或每历史姓名 SQL。保留原 actual owner/requester viewer、
  源修订、完整 lineage、fresh 权限和外部 rank/time I/O 后当前性/唯一性证明。
  原姓名必要见证与目标组必须共同 fit；本人自指、私聊及跨群权限规则不变。

## 完整原文证明与显式迁移

`fact_names.grounded` 为新草稿、commit 和读取视图共用的规则：保留 quote 必须含该
本人自报，且它在完整原 source 的确切 occurrence 必须处于非转述/非条件/非引文边界。
所有 lineage/evidence 来源集合必须相等，且每条都通过原真实 owner/来源 fresh 校验。
任何 key（包括旧 `identity.name`）缺少 `source_text` 或原文边界不成立，都不进入
`NameEntry`，不能借新证据替旧 NULL 整组背书。

`automatic_evidence` 仅增加 nullable `source_text TEXT`。保留原 quote，不把证明藏在
metadata/旧 hash，不引入 opaque 凭证、网络读缓存或新的 RPC。该正文沿 `_content`
已有累计 65,536-byte 限制并在共用规则中检查单原文上限；普通事实、宠物/书名事实不复制
原文。正文不进入搜索索引、known、portable unit 或响应；随既有 evidence/group 保留规则。

内部 `automatic_fact_schema` 显式 1→2：`migrate-facts` 沿原备份、独立 source guard、
事务 DDL 和幂等路径执行，旧行全部保持 NULL。fresh SQLite/PG 为 2；旧 SQLite1 或
PG1 普通读写继续安全运行，不读取不存在的列，姓名写入须先显式迁移。
SQLite1 导入新 PG 建表时列已存在、metadata 仍 1；显式迁移允许这一状态且不填证据。
SQLite2 导入保留原证明和版本 2。PG ready/查询分支不偷偷 DDL。
schema1 普通事实仍可使用，但新本人姓名 commit 需要先执行显式 schema2 迁移，
否则返回 `dependency_unavailable` 503；这不是无需迁移的 binary 直接升级。

没有反向迁移。旧 binary 不认识 schema2，也可能使用旧三列位置式 INSERT；不能只回退
binary 就宣称兼容。需要配套迁移前数据库与独立 guard，并另行协调恢复；现有 Store 的
PG JSON 是备份证据，不代表已经实现生产恢复工具。本卡没有执行数据库恢复或生产迁移。

## 支持与保守拒绝的句式

有限明确自报包括 `我叫/我名叫/我现在叫/我还是叫/我改名叫`、
`我的/本人的名字/姓名/昵称是/叫/为`、`本人名叫/名为`、`大家(都)叫我`，
以及 `My name is`、`I am named/called`、`I'm called`。
明确过去姓名必须声明 historical；带日期的开始姓名必须有原有时间校验支持的 valid_from。
摘要可以使用本人自报、精确姓名值，或有限中性作者/用户姓名摘要；英文支持
`The author's/user's name/nickname is ...`、`... name: ...`、
`The author/user is named/called ...`，原 source 仍必须本人正向自报。

拒绝 `我是医生`（同样不据歧义 `我是阿川` 推断姓名）、第三人/父亲/朋友姓名、
宠物/书名、疑问、假设/条件、否定及整句引文。不能从别人说的
`“我叫阿川”` 内部截一段规避新草稿对完整原 source 的校验。
`我叫“不叫小禾”` 或姓名值本身含引号/问号可作为完整 quoted literal；
这与整段 `“我叫小禾”` 引文不同。不是自由自然语言姓名识别器，也没有按评测名字堆规则。
