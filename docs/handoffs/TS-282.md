## 问题与实现

第四轮隔离实测中，对象名被模型解释污染，例如把当前“晚晴”存成
“晚晴（旧名：红叶）”，把明确不改名的蓝本存成“暮色（不改名，不叫晚星）”。
原 `may_replace()` 对所有 name/title 直接允许替代，也会让新的名称否定或重申退役原名称。

新增有限字面规则集中在 `fact_labels.py`；准入和更新意图共用同一声明识别规则。
候选仍先经过既有 schema、来源全文/摘要核对、证据定位、人物 scope 与实体校验。
对象 name/title 必须在验证过的完整 source 中找到同对象的完整命名声明，且每个 quote
覆盖完整声明。模型的 statement、known_facts 和 negations 不充当来源证据。
不修剪括号、不替模型猜值、不用 substring 命中把解释或旧值补成新名。

有限规则覆盖现有猫/狗名称、狗名词同位语、同句代词、书本序号、颜色对象、
更名/仍叫/旧名及显式引用题名。当前名与历史名各自匹配相应声明，不能交换 state。
真正字面题名中的括号、“旧名”、否定词和条件词保持原值；引号内的词不执行为命名、
时间、条件或否定操作符。未引用的条件、命名禁止/停止和否定不证明正向当前名。
名字型 entity.mention 仅在等于完整 literal 时可借已声明种类识别主体，不能从 literal
内部截出“妹妹”等碎片建立拥有者；同位语主体也不拼入待证名字。

拒绝保持既有整批原子性与有界重试：同批一个名称无证据就拒绝整个 proposal，
不写半批事实或 write ledger；相同 job 可以提交修正后的输出。
纯名称否定可继续作为无 positive name/title 的普通证据保存，不用负向 label 替代当前名。

### 更新、重申与来源

对象 label 的更新意图只读取该 current group 的实际 source quote；两个提交时间方向
分别使用各自 current group 的 quote，不用模型摘要判更名。
当前 draft 先复用已有 quote；确实需要旧组证据时按 `GROUP_READ_BATCH` 批读，
非对象 label/author 路径不增加读取。没有增加 Store、缓存、表或持久隐藏证明。

同字面重申不退役原事实，原有效期、重复合并、来源 lineage 和新增否定证据保留。
source 证明的肯定更名可以携带原样条件数组，例如真实 RED_SOURCE 的 `conditions=['以后']`；
模型条件数组不作为更新控制依据。实际“如果/假如/假设”来源仍被拒绝。
author-name 继续走既有 `fact_names`，非 label 的 restricted-denial 保护不变。

新准入证明绑定，更新意图仅证明原组 quote 的正向性。旧对象行不会被追溯提升为
“已由新全文规则认证”；旧 quote 没有完整 source 的情况下不会补造证明或回填历史。
本卡不迁移或清洗真实已有数据。

### 纯名称摘要的自然召回

顺序/逆序集成先证明数据库仅保留最新字面名，但暴露了另一条实际遗漏：statement
只有 literal 时，索引虽含对象，原 `Constraints` 只看 statement，蓝封面约束会拒绝它。
协调者据此扩入 `recall_index.py`。

仅当已有授权完整同组快照含对象 name/title、单 unit、有 entity 且 statement 严格等于
fact.value 时，约束文本使用该组已绑定 entity 的 mention 和既有 kind 词汇；
mention 本身等于 literal 时只用 kind，避免名称里的“狗/妹妹/否定”变成真实对象或 owner。
不借整个 quote 的另一对象，不改搜索索引、原 statement、输出 unit、普通完整陈述、
无 snapshot 的 profiles 路径或无 entity 情形，也不增加查询。
人物/私聊/异群授权、完整组与 lineage、当前性、外部 I/O 后 freshness 仍沿原路径。
