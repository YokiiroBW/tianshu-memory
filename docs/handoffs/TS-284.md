`entity={id:null,kind:dog,mention:狗蛋挞}`，不是把宠物名抽成本人姓名。

安全实际业务投影把这个兼容反例与真实三次 proposal 对齐；没有读取隐藏推理或原始 ledger。

## 集中的修复

沿既有同位语解析保留来源确定的 typed noun 与完整 literal span，仍先从 source
动作/完整引用边界确定名称末端，再与模型 value 全等比较，不能由模型 value 决定切点。
有限词汇仍来自现有 `NOUNS/OBJECT_NOUNS`；优先完整 noun，避免“猫咪＋糖球”被切成
“猫＋咪糖球”。

原 typed head、完整名字型 mention、legacy null entity 路径保留。
新增 composite 分支只接受在同一个 source 出现中连续覆盖 typed noun 和整个 literal、
准确结束在已解析名称边界的完整 mention；允许真实左侧“我家／第二只”等描述。
主体核验只接这个 span 去掉已证明 literal 后的真实 head。
不接纳名字截片、借另一个对象的 mention、quoted 转述、错误种类、条件或否定来源。
原 quote 完整覆盖、当前/历史、原子性、重试、有效期、来源/权限与整组保护不变。

同一有限分解复用于原 bare-literal constraint 分支：完整 composite 中的 literal
只作为名字，不让“我妹妹的狗”等名字内容制造真实亲属 owner 或对象种类。
仍仅处理已有授权完整同组快照、单 unit、有 entity 且 statement 严格等于 fact.value 的路径；
普通完整 statement 与不支持的非同位语 mention 保持原逻辑，无新增 SQL/source 查询。
保留 entity.mention、ID、fact.value、原 unit 和索引原文；不把“狗蛋挞／狗豆包”改成
泛化“狗”，避免把不同宠物合并。这个约束投影也不追认旧行已经过新的 source 认证。
