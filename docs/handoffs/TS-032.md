## 变更及可观察行为

`Authenticator.resolve` 新增可选 `callers.<service>.issuer_ca_file`，要求非空绝对
PEM 路径，以标准库 SSLContext 验证该 CA 签发的 issuer。配置逐请求读取，现有
`configured_app()`、CLI、factory 无需新增参数或替换认证器即可使用。
省略配置仍使用原有 HTTPX 默认可信根；固定 HTTPS、`trust_env=False`、
`follow_redirects=False` 保持不变。没有 verify=False 开关或任意 transport 注入。
错误/损坏/缺失 CA、相对路径/false、握手失败明确 503，不回退默认根或明文。

新测试直接使用产品 `configured_app` + 真实 loopback HTTPS 合成 issuer，未替换
Authenticator 或来源权威。每轮生成隔离 CA、服务器证书、错误主机名/客户端用途/
过期证书；TLS 握手失败时服务器未收到 HTTP 凭据或正文，身份注册无落库。
证书/私钥仅在本任务 .runtime，CA 私钥不持久化，未操作系统证书库。

通过的行为：可信 CA 下 register 创建身份、resolve 返回同一 person；错误 CA 轮换立即
拒绝且换回恢复；环境代理与 CA 不影响显式信任；默认证书校验拒绝隔离 CA；错误 CA、
主机名、证书用途、有效期、配置类型/路径均拒绝；HTTP 拒绝；301/302/307/308 不跟随；
issuer 401/403/404 映射 forbidden，500 映射 503；错误 resolver token、issuer、caller、
receiver、assertion_ref、请求关联、账号、actor、到期与实时撤销均拒绝。
错误响应不泄漏上游正文或测试凭据。

来源保持 `None`：身份 HTTPS 成功之后，health、select（普通/零预算）、
profiles/select（零预算）、revise、turn-commits 仍为 503，无来源工作或记录写入。

## 来源候选、剩余缺口与下一步

[来源接线候选](../candidates/TS-032-source-authority.md) 对照固定 Platform
`a5ee59ff67a2de7a7e0d8328ea3c0f43e1d6a209`、Core
`812019e287a5bf37d9b5d810a028ffea828b872e` 和本任务 Memory 基线，记录了：

- Platform 公开 origins 解析 HTTP 与 prepare/confirm/source 检查应用端口的区别；
  `verify_current_sources` 不验证归档、receipt 或 Memory scope_version，不能直接充当来源权威。
- Core 当前受理/revision/retract/context_revision 与真实输入回执归属；缺少可供 Memory
  使用的源快照、修订/撤销同步和读取屏障接口，不能读取对方数据库来接通。
- Memory 本地 verify/current、source revision/epoch、lineage 和原子失效职责；普通 scope
  与画像公开/群 epoch 分属不同版本域，零预算探针也须覆盖实时源/权限失效。
- 身份映射与来源验证避免依赖 turn_committed 或 Memory 查询形成循环；撤回、更正、
  遗忘、共享批准、原文删除分别由对应事实 owner 负责，生产确认/批准 issuer 仍缺失。
