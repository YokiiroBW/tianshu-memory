# Sourced automatic fact quality (TS-132)

Automatic extraction now carries a stable predicate, canonical value, explicit time range and source-language topic terms. The authenticated source event still owns person, actor, conversation, audience and reality. Exact source quotations are checked before every normal candidate commit. No model output grants access or publishes a profile.

Equivalent facts within the same scope reuse their record/group and retain all original source lineage and quotations. A later current value supersedes the former value without erasing its version history. Historical statements do not override the current value. Ordinary recall excludes superseded values; explicit historical questions may retrieve them with their historical validity label. Current-time queries also exclude expired or historical facts. Future-effective facts are excluded until their date. The predicate and equivalence judgment remain extractor-dependent; this is not a vector service or a guarantee for every paraphrase.

The keyword index includes verified original-language quotations and bounded topic aliases. Permission/source filtering precedes ranking. Existing historical records are preserved and are not silently rewritten or retroactively classified by this migration. Formal profiles remain separate from private evidence. Local user action `prepare_evidence_profile` builds a reviewable draft from exact current record versions under an existing profile grant; the existing `approve_profile` and `publish_profile` operations are still required. Expired, historical, superseded or unauthorized evidence cannot become a current profile through this preparation action.

Successful explicit context writes own their exact source revisions. Automatic extraction leaves that source's text empty, completing its normal no-op candidate receipt rather than writing a second copy. Other messages in an aggregate remain eligible. This conservative policy means additional facts in a single explicitly handled message must be included in that explicit proposal; it avoids a second independent inferred copy, including after forgetting.

## Migration and rollback

With Memory writers stopped, run `python -m tianshu_memory.cli --config <existing-config> migrate-facts --backup <new-local-backup>` (confirm CLI placement using `--help`). It requires the existing guarded schema 3, produces an exclusive SQLite backup plus its matching independent source guard, and adds only `automatic_facts`, `automatic_evidence`, indexes, revision triggers and a schema marker. No startup migration, source rewrite, person creation, permission expansion or synthetic production data is performed. Existing private records and all authority tables must match before/after migration; the source revision and the matching guard advance normally.

Old binaries retain schema-3 compatibility with the additive tables, so rollback should normally change images while retaining current data. A cold database restore must use the matching DB/guard pair and is appropriate only when no later writes would be lost. Never combine an old DB with the newer independent guard or repair the guard by hand. Existing data remains the authority; migrations do not backfill old inferred facts.
